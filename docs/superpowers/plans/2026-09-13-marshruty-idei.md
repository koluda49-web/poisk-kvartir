# План: 11 улучшений маршрутов

Дизайн: `docs/superpowers/specs/2026-09-13-marshruty-idei-design.md`.
Ветка: `marshruty-idei`. Рабочая папка: `C:\Users\User-NUC\Desktop\Поиск квартир`.

## Global Constraints

1. **Один файл сервера** `kvartiry-server.js` (~7100 строк, Node без зависимостей). Сайт — строки HTML/JS внутри него.
2. **Главная страница** — шаблонная строка `const PAGE = \`…\`` (около строки 3600). Внутри неё в клиентском коде **нельзя** обратные кавычки и `${`; **обратная косая черта съедается** шаблоном — в регулярках либо обходиться без `\`, либо удваивать (`\\d`). После правки обязательно `node проверки/скрипт-страницы.mjs` (разбирает скрипты страниц).
3. **Страница маршрута** `marshrutPage(ids)` (около строки 2830) собирается сложением строк в одинарных кавычках; клиентский код внутри — строки, кавычки в нём экранируются как `\\"`. Смотри существующие куски рядом и повторяй их стиль.
4. Стиль: русские имена функций и переменных там, где их использует окружающий код; комментарии по-русски и объясняют «зачем». Палитра: акцент `#9a3412`, текст `#1c1917`, фон `#faf7f3`, линии `#e9e2d8`; на главной — CSS-переменные (`--accent`, `--txt-2`, `--line`, `--surface-2`). Тёмная тема на `/marshrut` — через уже существующий блок `@media (prefers-color-scheme:dark)`.
5. **Без флагов, политики и рекламного вида.** Не выдумывать фактов в текстах о местах.
6. **Лёгкость:** ничего тяжёлого при загрузке страниц; новые серверные запросы кэшировать функцией `cached(ключ, fn, ttl)`.
7. **Процессы.** НИКОГДА `taskkill /IM chrome.exe`, `/IM node.exe` или любое убийство по имени — у владельца открыт свой Chrome. Локальный сервер перезапускать только по PID:
   `PID=$(netstat -ano | grep ":8080 " | grep LISTENING | awk '{print $5}' | head -1); [ -n "$PID" ] && taskkill //F //PID $PID; (node kvartiry-server.js > "$TEMP/srv8080.log" 2>&1 &)` и ждать `curl -s http://127.0.0.1:8080/ping`.
8. **Проверки в браузере** — по образцу `проверки/своя-точка.mjs` (CDP, headless Chrome, свой `--user-data-dir`, `chrome.kill()` в конце). Порт у каждой новой проверки — фиксированный, из задачи. Не запускать две проверки одновременно. Итоговая строка `Пройдено N, падает M`, код выхода 1 при падениях. Добавить скрипт в `package.json` (`"проверка-…": "node проверки/….mjs"`).
9. **Существующие проверки должны проходить** после задачи: `места`, `поездка`, `вкладки`, `возврат-и-фильтры`, `маршрут-на-карте`, `своя-точка`, `скрипт-страницы`; для задач, трогающих общие страницы или API, ещё `страницы-и-выдача`.
10. **Коммит** в ветку `marshruty-idei`, сообщение по-русски (что и зачем), последняя строка `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`. Не пушить.
11. Существующие соглашения маршрута: точки `{id, name, addr, lat, lng}`; свои точки имеют id `m<lat5>_<lng5>`, в ссылке `m…~Имя`; `localStorage.route` — массив точек; на главной `window.__route`, `routeToggle`, `dropRoute`, `orderRoute`, `drawRoute`, `рисоватьМаршрутНаКарте`; на `/marshrut` глобальные `Т`, `карта`, `нарисовать()`, `сохранить()`, `добавить(p)`, `убрать(id)`, `порядок()`, `подорогам()`; `/api/route?p=lat,lng;…` → `{ok, km, minutes, legs, line}`.

### Task 1: Будильник и постоянное хранилище

**Будильник.**
- Если `process.env.RENDER_EXTERNAL_URL` задан, сервер каждые `SELF_PING_MS` (env, по умолчанию `540000`, 9 мин) делает `fetch(RENDER_EXTERNAL_URL + '/ping?self=1')`. Таймер `.unref()`. Ошибки — одна строка в лог, без падения. Первый пинг — через `SELF_PING_MS` после старта.
- Счётчик удачных/неудачных пингов и время последнего удачного — показать на `/stats` одной карточкой «Будильник» (включён/выключен, последний ответ N мин назад).
- В `.github/workflows/keepalive.yml` поправить комментарий: GitHub запускает расписание с задержками в часы, это запасной вариант после перезапуска. Расписание не менять.

**Постоянное хранилище.**
- `DATA_DIR` (env, по умолчанию `__dirname + '/данные'`). Функции:
  - `прочитатьДанные(имя, поУмолчанию)` — синхронно читает `DATA_DIR/<имя>.json`, при ошибке возвращает `поУмолчанию`.
  - `записатьДанные(имя, объект)` — сразу пишет локальный файл (создаёт папку); если заданы `GH_TOKEN` и `GH_REPO` (по умолчанию `koluda49-web/poisk-kvartir`), ставит отложенную отправку в GitHub: не чаще раза в `GH_SYNC_MS` (env, по умолчанию `600000`) на каждое имя; отправка — `GET` содержимого за `sha`, затем `PUT {GH_API}/repos/{GH_REPO}/contents/данные/<имя>.json` (путь URL-кодировать по сегментам) с `message: "данные: <имя> [skip render]"`, `branch: GH_BRANCH || 'main'`, контент base64. `GH_API` (env) по умолчанию `https://api.github.com`. Заголовки `Authorization: Bearer`, `User-Agent`, `Accept: application/vnd.github+json`. Ошибки — в лог и в состояние, не бросать.
  - При `SIGTERM`/`SIGINT` отправить отложенное немедленно (в том же обработчике, где сохраняется статистика; не более 8 с ожидания).
- На `/stats` карточка «Постоянное хранилище»: включено/выключено (нет `GH_TOKEN`), последняя удачная отправка, последняя ошибка.
- Папку `данные/` не добавлять в `.gitignore` (файлы в ней — часть репозитория). Создавать её пустой не нужно.

**Проверка** `проверки/будильник-и-хранилище.mjs` (без браузера):
- поднимает мок GitHub на `127.0.0.1:9612` (запоминает запросы; на GET отвечает 404 первый раз, дальше `{sha:"abc"}`; на PUT — 201);
- запускает второй экземпляр сервера `node kvartiry-server.js` с env `PORT=8097`, `RENDER_EXTERNAL_URL=http://127.0.0.1:8097`, `SELF_PING_MS=1500`, `DATA_DIR=<временная папка>`, `GH_TOKEN=test`, `GH_API=http://127.0.0.1:9612`, `GH_SYNC_MS=500`, `KUFAR=off REALT=off FLATBOOK=off CHECKIN=off KVARTIRKA=off`; ждёт `/ping`;
- проверяет, что за 5 с в лог/на `/stats?key=poisk2026` видно ≥2 удачных пинга;
- для проверки записи добавить служебный маршрут **только при `DATA_TEST=1`**: `POST /api/_data-test` с телом `{имя, объект}` вызывает `записатьДанные`; проверка вызывает его, убеждается, что локальный файл появился и что мок получил `PUT` с правильным путём, `message` содержит `[skip render]`, контент декодируется в тот же объект;
- завершает свой экземпляр сервера по его `child.pid` (child_process) и мок; удаляет временную папку.

Порт проверки браузера не нужен. Скрипт в package.json: `проверка-будильника`.

### Task 2: Ручной порядок точек — перетаскивание

**Где:** список на `/marshrut` (`#rlist .it`) и блок «Маршрут на день» на главной (`#rtList .rt-item`).

- У каждой строки слева ручка `⋮⋮` (`<button class="drag" type="button" aria-label="Перетащить">`). Перетаскивание через Pointer Events (мышь и палец): строка едет за указателем, на месте — пустая полоска-заместитель, после отпускания порядок применяется. На телефоне прокрутка страницы при перетаскивании не должна срабатывать (`touch-action:none` на ручке). Клавиатура: на ручке `ArrowUp`/`ArrowDown` двигают точку на одну позицию.
- После перестановки: режим `manual`, сохранение (`localStorage.route` в новом порядке, `localStorage.routeOrder='manual'`), перерисовка номеров, меток на карте, линии, км и перегонов по дорогам.
- Режим `manual`: функции порядка (`порядок()` на `/marshrut`, `orderRoute()` на главной, `порядокОбъезда()` на сервере при `o=1`) возвращают список как есть; новые точки добавляются в конец.
- Кнопка «Упорядочить автоматически» (текстовая, рядом со сводкой) видна только в `manual`; нажатие — `routeOrder='auto'` и пересчёт.
- Ссылки: в `manual` к `/marshrut?p=…` добавляется `&o=1` (на главной — `#routeGo`, `#routeBar`; на `/marshrut` — `history.replaceState`). Сервер: `/marshrut` читает `o=1` и не пересортировывает; клиент при открытии ссылки с `o=1` ставит `routeOrder='manual'`, без `o` — не трогает сохранённый режим, но показывает порядок из ссылки отсортированным как сейчас.
- События `storage`/`visibilitychange` учитывают и `routeOrder`.

**Проверка** `проверки/порядок-маршрута.mjs`, порт **9601**:
- на `/marshrut?p=5069,286,910026` перетаскивание третьей строки на первое место синтетическими `pointerdown/pointermove/pointerup` → порядок имён в списке изменился, номера меток на карте 1..3 в новом порядке, в адресе `o=1`, в `localStorage.routeOrder` — `manual`;
- перезагрузка — порядок сохранён; «Упорядочить автоматически» — кнопка исчезла, порядок как у `порядок()`;
- стрелка вниз на ручке первой строки меняет две точки местами;
- открытие `/marshrut?p=286,5069,910026&o=1` в чистом профиле — порядок ровно как в ссылке;
- на главной (`/?country=places`): три точки через `routeToggle`, перетаскивание в `#rtList` → порядок в `window.__route` и в `#routeGo` (`o=1`);
- новая точка в ручном режиме встаёт в конец;
- в консоли нет ошибок.

### Task 4: «Поделиться» и «Сохранить картинкой»

На `/marshrut` и `/m/<slug>`, в ряду с «Открыть маршрут в Яндекс.Картах».

**Поделиться** (`#rShare`):
- если есть `navigator.share` — `navigator.share({ title: <заголовок страницы>, text: 'Маршрут на день: N точек', url: location.href })`;
- иначе — выпадающее меню: «Скопировать ссылку» (`navigator.clipboard.writeText`, при отказе — поле с выделенным текстом), Telegram `https://t.me/share/url?url=<url>&text=<текст>`, Viber `viber://forward?text=<текст>%20<url>`, WhatsApp `https://wa.me/?text=<текст>%20<url>` (всё через `encodeURIComponent`, ссылки `target="_blank" rel="noopener"`). Меню закрывается по клику вне и по Escape.
- После «Скопировать» — надпись «✓ Ссылка скопирована» на 1,6 с.

**Сохранить картинкой** (`#rPng`), функция `window.собратьКартинку()` → `Promise<Blob>` (PNG):
- холст 1080×1920, фон `#faf7f3`;
- верх 1080×1080 — карта: масштаб подбирается так, чтобы все точки и линия влезли с полями 90 px (zoom 5..15), плитки `https://tile.openstreetmap.org/{z}/{x}/{y}.png` через `Image` с `crossOrigin='anonymous'`; ожидание плиток не дольше 6 с — не пришли, рисуем без подложки; линия по дорогам из `/api/route` (`line`), если есть, иначе прямые; метки — кружки `#9a3412` с белым номером (свои точки — `#1c1917`); внизу карты мелко «© OpenStreetMap»;
- низ — заголовок страницы (жирный, до 2 строк), под ним сводка «N точек · X км · за рулём Y» (что есть), затем список до 10 строк «номер · название · адрес» (длинное — многоточием), при большем числе «и ещё K»; в самом низу `poisk-kvartir.onrender.com` + путь страницы (`/m/<slug>` или `/marshrut`);
- шрифт — системный sans-serif; ничего рекламного, без флагов.
- Нажатие кнопки: пока собирается — «Собираю…»; затем, если `navigator.canShare && navigator.canShare({files:[file]})` — `navigator.share({files:[file]})`, иначе скачивание `маршрут.png` через `<a download>`.

### Task 6: План дня, калькулятор топлива, поездка на два дня

**План дня** (`#rPlan`, при ≥ 2 точках):
- поле «Выезд» (`<input type="time">`, по умолчанию `09:00`, запоминается в `localStorage.routeStart`);
- таблица по точкам: время приезда, выбор «пробыть» (15, 30, 45, 60, 90, 120, 180 мин; по умолчанию 45; запоминается по id точки в `localStorage.routeStay` как объект), время отъезда; дорога между точками — `legMinutes` из `/api/route`, пока их нет — оценка по прямой ×1,3 при 60 км/ч с пометкой «примерно»;
- итог: «Последняя точка — до HH:MM». Переход через полночь показывать как «+1 день».

**Сколько стоит дорога** (`#rFuel`) — три поля, редактируются:
1. «Расстояние, км» — подставляется из км по дорогам (или по прямой ×1,3, пока нет), при правке человеком перестаёт обновляться сама; рядом ссылка «↺ по маршруту» возвращает автоподстановку;
2. «Расход, л на 100 км» — по умолчанию `7.5`;
3. «Цена литра, BYN» — по умолчанию `2.60`.
Итог сразу при вводе: «≈ L л · ≈ S BYN» (литры с одним знаком, рубли с двумя). Запятая как десятичный разделитель тоже принимается. Расход и цена — в `localStorage.routeFuel`.

**Два дня** (флажок `#rTwo`, при ≥ 3 точках):
- ночёвка по умолчанию после точки, где накопленные км (по дорогам, иначе по прямой) впервые ≥ половины; выбор «Ночёвка после точки N» (1..n-1);
- список получает заголовки «День 1 · X км» и «День 2 · Y км»; план дня считается для каждого дня отдельно с тем же временем выезда;
- между днями блок «Ночёвка рядом с «<название>»»: до 4 карточек жилья из `/api/places/stay?lat=&lng=&r=30` (снимок, название, цена, источник, ссылка на объявление в новой вкладке) и ссылка «Всё жильё рядом →» (на поиск главной рядом с точкой — посмотреть, как это делает кнопка «Жильё рядом» на карточке места, и повторить ту же ссылку/параметры); пусто — «В 30 км жилья не нашлось»;
- кнопка Яндекс.Карт превращается в две: «День 1 в Яндекс.Картах», «День 2 в Яндекс.Картах»;
- в ссылке `&d=N`; при открытии ссылки с `d` — флажок включён, ночёвка после N; картинка (Task 4) при двух днях ставит в списке разделители «День 1», «День 2».

**Проверка** `проверки/план-дня.mjs`, порт **9605**:

### Task 9: «Чаще всего добавляют в маршрут»

- Клиент: событие `route_add` отправляет `id` добавленной точки (на главной — в `routeToggle` и при своей точке `id:'m'`; на `/marshrut`, `/m/…`, `/podborka/…` — отправлять тем же форматом в `/api/t`, добавив там маленькую функцию отправки, если её нет). `T_FIELDS` на сервере должен пропускать `id`.
- Сервер: при `route_add` с числовым `id`, не робот — увеличивать счётчик в хранилище `популярное` (`{ <id>: число }`), но один посетитель (`v`) — один голос за точку (множество `v|id` в памяти, до 50 000 записей, старые выбрасывать). Сохранение через `записатьДанные` не чаще раза в 10 минут (локально) — отправка в GitHub идёт по правилам Task 1.
- `GET /api/places/popular` → `{ items:[{id,name,addr,pic,count}] }` — до 12 точек с `count ≥ 2`, по убыванию; если таких < 4 — `items: []`. Кэш 10 мин.
